# VCP Repository Evaluation Report

## Version / commit inspected
Record the repository package version, methodology version, and commit or tag inspected.

## Files inspected
List the files and directories you actually inspected. Mention if manifests, benchmarks, and route docs were included.

## Commands run
List the commands you ran or the outputs you verified.

## Current capability map
Summarize the current product layers: intake, routes, adoption packs, CLI, manifests, benchmarks, review, operations, backlog, examples, and docs.

## What VCP is
Describe the toolkit as it exists today, not as a future category leader.

## What VCP is not
State boundaries such as no offensive tooling, no compliance certification, and no human-review replacement.

## Methodology maturity
Score the methodology separately from tooling maturity.

## Tooling maturity
Assess the local CLI, npm wrapper, manifests, benchmarks, and validation path.

## AI-agent usability
Assess how easy it is for an external AI agent to classify, route, inspect, and evaluate VCP correctly.

## Practical adoption value
Explain where VCP is immediately useful for real repos today.

## Public standard maturity
Assess external proof separately. Do not infer standard status from internal completeness.

## Distribution maturity
Assess npm, packaging, install paths, hosted docs, and broader ecosystem availability honestly.

## Strengths
List the strongest current qualities.

## Weaknesses
List missing layers, rough edges, or confusing areas.

## Missing evidence
Record what external proof, case evidence, or distribution signals are still missing.

## Recommended use cases
Describe where VCP is a strong fit.

## Not recommended for
Describe where VCP should not be treated as the only answer.

## Scores
Use separate category scores instead of one compressed number.

## Confidence
State your confidence based on the actual inspection depth.

## Evaluation completeness
Mark the evaluation as `full` or `partial / shallow`.

## Shallow-evaluation warning
If manifests, benchmarks, CLI docs, or route docs were skipped, say so explicitly here.
