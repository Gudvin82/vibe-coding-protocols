# Spec Change Control

`vcp-version: v0.5.9`

When scope changes after implementation starts:
1. record the change in `SPEC_CHANGELOG.md`;
2. state why the original spec is no longer enough;
3. update acceptance criteria if behavior changes;
4. note architecture impact if cross-layer behavior changes;
5. decide whether tasks or backlog items must be re-sliced;
6. rerun spec review when the change is material.

Do not silently fold scope changes into implementation.
