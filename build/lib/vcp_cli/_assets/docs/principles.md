# VCP Principles

These principles define VCP's operating identity.
They are practical rules, not ceremony.

1. Build with AI. Ship with control.
2. Selective adoption, not whole-repo copying.
3. Smallest safe workflow.
4. Memory before major change.
5. Review before merge.
6. Diagnostics before release.
7. Proof without fake metrics.
8. Score is a readiness signal, not certification.
9. Public growth without spam.
10. Human accountability remains required.

## What VCP refuses to become

- not a personal assistant;
- not a security scanner;
- not a pentest or offensive toolkit;
- not a spec-kit clone;
- not a fake proof generator;
- not a replacement for human review;
- not an IDE or plugin marketplace unless actually published.
