# Adoption Tiers

VCP now exposes three practical adoption tiers.

## VCP Lite

Use when:
- solo developer;
- pet project;
- low-risk MVP;
- early AI coding.

Includes:
- AI intake;
- adaptive spec depth;
- minimal backlog;
- review-diff;
- score.

## VCP Team

Use when:
- shared repository;
- small team;
- client work;
- visible backlog and architecture memory are needed.

Includes:
- project memory;
- `PROJECT_BACKLOG.md`;
- `ARCHITECTURE_SOURCE_OF_TRUTH.md`;
- PR Gate;
- release readiness.

## VCP Governed

Use when:
- production;
- auth, payment, or sensitive data;
- compliance-sensitive delivery;
- agency/client release pressure.

Includes:
- governed spec path;
- release readiness;
- architecture drift check;
- third-party review;
- pack security;
- score and reporting.

## Selection rule

Start with the smallest tier that creates control.
If risk increases, move up a tier instead of copying the whole repository.
