# License

Repository package: `v0.8.9`

VCP uses a dual-license model so teams can reuse the code surfaces easily without weakening attribution expectations for the methodology.

## Code license

Code, CLI, scripts, tests, CI examples, and executable examples are MIT-licensed.

This covers practical reuse of:
- `vcp_cli/`
- `scripts/`
- `tests/`
- `ci-examples/`
- `setup.py`
- wrapper/package metadata

## Documentation and methodology license

Docs, methodology, diagrams, presentations, checklists, and case-study narrative material remain under CC BY 4.0.

This covers:
- `README.md` and `README_ru.md`
- `docs/`
- `docs_ru/`
- `protocols/`
- methodology-heavy `templates/`
- `assets/diagrams/`
- `assets/presentations/`
- `case-studies/`

## Why dual license

- MIT keeps code/CLI adoption friction low.
- CC BY 4.0 preserves attribution expectations for the methodology and teaching material.
- The repository stays honest about the difference between reusable code and reusable guidance.

## What users can do

Under MIT for code:
- copy, modify, bundle, and redistribute the code surfaces;
- use the CLI and scripts in commercial settings.

Under CC BY 4.0 for docs/methodology:
- copy and adapt the methodology with attribution;
- translate, remix, and republish the material with clear credit.

## Attribution expectations

For methodology/docs reuse:
- credit Vibe Coding Protocols;
- keep a link to the repository or the CC BY 4.0 license;
- indicate whether you modified the material.

Both code and methodology are provided without warranty or certification.
