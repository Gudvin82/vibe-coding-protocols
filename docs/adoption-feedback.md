# Adoption Feedback

Use this file when you want to try VCP on a real project and send useful feedback.

## How to try VCP on a real project

1. Choose the smallest route that matches the project.
2. Copy only the first templates you actually need.
3. Run `vibe-check` before and after your first safe slice.
4. Record what changed with evidence, not impressions only.

## What feedback helps most

- which route you chose;
- which templates you copied first;
- which checks were useful or noisy;
- which docs felt redundant or unclear;
- what you still had to invent yourself.

## What not to share

Do not share:
- secrets or tokens;
- customer data;
- internal endpoints or IPs;
- private architecture notes;
- anything that would not be safe in a public GitHub issue.

## Before / after evidence

Useful evidence can include:
- command output;
- small diffs;
- backlog findings;
- route selection notes;
- accepted risks.
