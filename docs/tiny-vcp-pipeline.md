# Tiny VCP Pipeline

<!-- vcp-version: v0.9.1 -->
<!-- methodology-version: v1.4 -->

Tiny VCP Pipeline:

`Charter -> Intent -> Plan -> Gate -> Proof`

- Charter: rules of the project.
- Intent: what is changing and why.
- Plan: how VCP routes/adopts the work.
- Gate: what must pass before PR/release.
- Proof: evidence that claims are not overclaimed.

## Copy this into AI

Use the Tiny VCP Pipeline:
1. Confirm project charter/rules.
2. Capture change intent.
3. Propose a plan.
4. Define PR/release gate.
5. Produce proof and limitations.
Do not write code before the intent and gate are clear.
