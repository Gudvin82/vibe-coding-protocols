# Migration Notes: v0.3.0 to v0.4.0

Use this guide if your project already copied VCP artifacts before
Maintenance Refactoring was added.

## What was added in v0.4.0

New commands:
- `commands/care-refactoring.md`
- `commands/ui-refactoring.md`

New report templates:
- `templates/reports/refactoring-report.md`
- `templates/reports/ui-refactoring-report.md`

New route references:
- maintenance refactoring for existing working projects;
- UI component ownership cleanup for frontend drift.

## Minimal adoption path for existing users

Copy at minimum:
- `commands/care-refactoring.md`
- `commands/ui-refactoring.md`
- `templates/reports/refactoring-report.md`
- `templates/reports/ui-refactoring-report.md`

Then update local route guidance:
- add maintenance route references to local `START_HERE.md` or equivalent;
- update local `PROJECT_MAP.md` or `PROMPTS.md` if you use them for routing.

## What not to overwrite blindly

Do not overwrite blindly:
- local `AGENTS.md`;
- local `SECURITY.md`;
- project-specific architecture docs;
- project-specific security or operations notes.

Review changes manually and merge only the parts that fit your project.

## Keep project-specific docs

Keep your existing:
- architecture docs;
- security baselines;
- accepted-risk notes;
- deployment or incident documentation.

The maintenance lane should extend them,
not replace them.

## Local validation after copying

After copying the maintenance artifacts,
run your local validation commands.
At minimum, re-run the route or readiness checks you already trust.

## Suggested minimal copy set

If you want the smallest v0.4.0 adoption set for an existing project:
1. `commands/care-refactoring.md`
2. `commands/ui-refactoring.md`
3. `templates/reports/refactoring-report.md`
4. `templates/reports/ui-refactoring-report.md`
5. local route references in `START_HERE.md`, `PROJECT_MAP.md` or `PROMPTS.md`
