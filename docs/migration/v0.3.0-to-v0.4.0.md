# Migration Notes: v0.3.0 to v0.4.0

Use this guide if your project already copied VCP artifacts before
Maintenance Refactoring was added.

## What was added in v0.4.0

New commands:
- `commands/care-refactoring.md`
- `commands/ui-refactoring.md`

New report templates:
- `templates/reports/refactoring-report.md`
- `templates/reports/ui-refactoring-report.md`

New route references:
- maintenance refactoring for existing working projects;
- UI component ownership cleanup for frontend drift.

## Minimal copy set for existing users

Copy at minimum:
- `protocols/maintenance/`
- `commands/care-refactoring.md`
- `commands/ui-refactoring.md`
- `templates/reports/refactoring-report.md`
- `templates/reports/ui-refactoring-report.md`
- `templates/examples/refactoring-report.filled.example.md`
- `templates/examples/ui-refactoring-report.filled.example.md`
- `docs/security-methodology-scope.md`
- `docs/tooling-roadmap.md`

Then update local route guidance:
- add maintenance route references to local `START_HERE.md` or equivalent;
- update local `PROJECT_MAP.md` or `PROMPTS.md` if you use them for routing.

## 15-minute adoption path

If you want the smallest safe adoption pass:
1. copy only the command files and report templates;
2. add one maintenance route note to local `START_HERE.md`, `PROMPTS.md` or `AGENTS.md`;
3. run one dry-run `/care-refactoring` review;
4. allow `NO_CHANGES_NEEDED` as a valid result.

## 60-minute adoption path

If you want one real scoped pass:
1. copy the maintenance protocols;
2. update your local `PROJECT_MAP.md`;
3. run one scoped maintenance pass;
4. produce a report;
5. do not merge code changes without validation.

## What not to overwrite blindly

Do not overwrite blindly:
- local `AGENTS.md`;
- local `PROJECT_MAP.md`;
- local `SECURITY.md`;
- project-specific architecture docs;
- project-specific security or operations notes.

Review changes manually and merge only the parts that fit your project.

## Keep project-specific docs

Keep your existing:
- architecture docs;
- security baselines;
- accepted-risk notes;
- deployment or incident documentation.

The maintenance lane should extend them,
not replace them.

## Local validation after copying

After copying the maintenance artifacts,
run your local validation commands.
At minimum,
re-run the route or readiness checks you already trust.

## When not to adopt yet

Delay v0.4.1 adoption when:
- the project is in an active incident;
- no one can review AI changes;
- no validation path exists;
- a security-sensitive change is being attempted without the hardening route.
