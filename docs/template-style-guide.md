# Template Style Guide

Use this guide when adding or updating VCP templates, prompts and checklists.

## Headings

- Start with what the artifact is for.
- Prefer short section titles.
- Keep section order predictable when possible.

## Purpose

Each template should make clear:
- when to use it;
- what decision it supports;
- what evidence should be stored there.

## Fields

If a field needs user input, prefer:
- `[FILL IN: short description]`

Instead of:
- bare `TODO`
- `TBD`
- empty mystery cells without explanation

## Examples

Add a short example when the field is easy to misunderstand.
Do not add fake adoption claims or fake production data.

## Evidence

When an artifact refers to checks or decisions, leave a place for:
- command or tool used;
- date;
- owner;
- accepted risk if relevant.

## Accepted risks

If a template may contain accepted risks, the template should help record:
- what the risk is;
- why it is accepted;
- who owns it;
- when it should be reviewed again.

## Placeholder policy

- placeholders should be obviously synthetic;
- examples should be sanitized;
- no real tokens, IPs or client data.
