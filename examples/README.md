# Examples

These examples are synthetic walkthroughs.

They are:
- not real customer projects;
- not production-ready applications;
- not claims about real deployments;
- sanitized and safe to study publicly.

## Start here

- If you want the full Starter-to-Hardening path, start with [`todo-app-vibe/`](./todo-app-vibe/)
- If you want a bot scenario, start with [`telegram-bot-vibe/`](./telegram-bot-vibe/)
- If you want the light route, start with [`landing-page-vibe/`](./landing-page-vibe/)
- If you want the fuller backend route, start with [`saas-backend-vibe/`](./saas-backend-vibe/)

## Walkthroughs

- [`todo-app-vibe/`](./todo-app-vibe/) — demonstrates Starter, Memory Bank, first slice and later Hardening findings
- [`telegram-bot-vibe/`](./telegram-bot-vibe/) — demonstrates bot-focused hardening and abuse/fallback thinking
- [`landing-page-vibe/`](./landing-page-vibe/) — demonstrates Light Hardening, mobile/device QA and public exposure checks
- [`saas-backend-vibe/`](./saas-backend-vibe/) — demonstrates fuller hardening for migrations, scanners, rate limits and backend readiness

## Legacy folders

Older example folders remain in the repository for continuity, but the `*-vibe/` folders are the preferred naming style going forward.
